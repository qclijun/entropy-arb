# 策略回放与分歧审计

请求套利机会优先级、收益、回测或核对冲突结论时读取本文件。

## 选择一致的策略与输入

优先使用项目 `entropy_arb/backtest.py` 和 `tools/backtest.py`，复用现有策略的阈值、费用、分片、库存加价和限额。先核对本次代码支持的参数及输出含义。自写单仓往返模型只作为另行命名的研究情景，不能称为生产策略回放。

在独立工作目录复制配置后修改研究参数；不改 `record/config-*.yaml` 或运行中的配置。用同一截止时间、可比较的样本、每腿资本／限额、数量规则、费用和执行假设比较候选。不同品种分别采用可解释的参数，不能用任意统一零中枢和带宽直接证明优劣。

示例参数需替换为本次研究值，输入须先按数据规则检查：

```bash
.venv/bin/python tools/backtest.py \
  --symbol <SYMBOL> --hedge <lighter|lighter-rh|tradexyz> \
  --config <研究配置.yaml> --env-file /dev/null \
  --csv <固定窗口副本.csv> \
  --extra-slippage-bps <每笔每腿不利滑点> \
  --trades-csv <本次工作目录/模拟成交.csv>
```

L1 分钟回放把该分钟末两腿盘口当作同时且足量可成交；没有真实深度、队列、部分成交或撮合时间证据。`assumed-depth-usd` 和数量规则是模型假设，不能据此证明实盘容量。分钟内最大 edge 不提供事件先后和信号持续性，不能作为撮合价格。

## 参数与验证

- 先确定策略、比较目标和成本情景，再查看验证区间收益。若参数用全量数据拟合，结果标为样本内。
- 需要验证稳定性时，用较早区间拟合参数，在后续区间固定参数验证；滚动参数只能使用当时已知历史。数据不足以形成独立验证时明确说明，不把近期拟合窗口当成验证。
- 至少对照基准费用与合理执行成本情景。延迟值只有实测证据才能称为实盘延迟；任意一分钟延迟是压力条件，不据此单独排除某品种。
- 报告成交批次、已闭合往返及未平仓位；生产引擎分片成交不等于独立完整往返。无法可靠关联往返时直接披露，保留逐笔成交与仓位路径。
- 小样本、单次状态切换贡献大部分收益、未平仓亏损或跨断档持仓，都限制收益排序。不得因历史日报失败永久排除某个场所。

## 开平规则与核算

明确平仓是到中枢、到另一侧阈值、超时还是实际风控动作。三者的收益不等价。所谓“往返净约为上轨+下轨”仅适用于两侧都在各自门槛成交、固定数量且扣假设费用的条件情景；不能用于中枢平仓、延迟成交、强制退出或实际收益承诺。

例如卖 Entropy／买 hedge 后再反向平仓，等基础数量 `q` 的现金价差收益为：

```text
gross = q * (E_bid_entry - H_ask_entry + H_bid_exit - E_ask_exit)
net = gross - 四笔名义手续费 - 额外执行成本 - 净资金成本 - 兑换成本
```

买 Entropy／卖 hedge 方向使用对应 bid/ask 反向核算。费用、价格和数量均按模拟逐笔记录，不用 UI 标签或模型建议代替实际成交。相同美元净敞口并不自动等于相同基础数量，需校验合约乘数与数量规则。

累计 bps 必须写明分母和规模方案。每次入场单腿名义归一后的 bps 相加不是账户收益率；不同持仓时长的结果也不能直接年化。美元示例注明单腿规模、资本占用和深度假设。

## 断档、期末仓位与收益标签

不知道未来会断档时，无法在断档之前最后一行执行预定平仓。禁止把这种退出计为在线可执行收益。若为分段诊断在各段末清算，标成事后区间末估值，并单列次数及金额。

模型若继续持仓跨过断档，记录次数、持续时间及不可观察风险；不能把缺失期间的资金费、最差净值和可平仓性视为已验证。

期末仓位按中间价估值与按 bid/ask 扣费清算不同。项目 `final_equity` 是模型估值，不能直接标为“已实现利润”。若追加期末清算计算，单列为假设清算估值，避免计入策略已完成往返。

核对逐笔现金流、四笔费用、期末仓位与总结果能够对账。无法拆出已实现部分时报告模拟净值、未平仓位及缺项，不虚构已平利润。

## 分歧审计

先固定双方原始证据：CSV 哈希／截止时间、清洗规则、费率、参数拟合区间、建仓／退出规则、滑点／延迟、库存限额、断档处理和收益标签。

一次只替换一个因素；改费率时既检查费用差，也检查触发和交易集合是否变化。用相同条件复算后，分别列出数值错误、方法差异与证据缺失。拿不到旧回测脚本和逐笔记录时，其结果为未核验；新模型的相反结果不能证明旧模型计算错误。
