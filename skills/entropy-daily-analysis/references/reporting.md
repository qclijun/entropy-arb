# 报告与证据要求

## 交付内容

先用中文说明本次能支持的结论：仅统计候选、通过哪些模拟验证、或证据不足。没有可比证据时不强行给第一名。

每份报告包含以下信息；正文保持精简，详细数据放入本次证据目录：

1. **样本与费用**：截止时间、时区、各组日历跨度／有效分钟／覆盖率／断档；每腿费率、来源及未核验项。
2. **每组统计**：全量及近期窗口的中枢、上／下轨、方向偏斜与漂移。阈值明确为样本内候选；触发频率注明分钟计数及归一分母。
3. **验证结果（如请求）**：策略与拟合／验证区间，成交批次、可关联的完整往返、未平仓位、模拟收益标签及成本敏感性。未验证项保持 `UNKNOWN`。
4. **判断边界**：哪些候选值得补采或继续验证、哪些证据支持暂缓、未知成本是否足以吞掉收益。区分收益不佳与数据不足。
5. **证据路径**：原输出、输入清单、参数与模拟逐笔记录；没有实际成交回执，不使用“真实收益／真实往返”措辞。

格式示例（缺项填 `UNKNOWN`，不要凑数字）：

```text
截至 <时间/时区>：<结论及证据等级>。
费用：Entropy <费率/来源>，对冲腿 <费率/来源>；<未知成本>。
<配对>：有效 <分钟>/<跨度>，中枢 <全量/48h/6h>，候选上/下轨 <值>；<漂移与限制>。
回放（若需要）：<策略、成本、区间>，<批次/往返/期末仓位>，<模拟净值或已平/估值拆分>。
证据：<本次目录>。
```

## 保存与停止

在用户指定的目录保存；未指定时使用项目内 `.scratch/daily-analysis/<日期>/<唯一运行标识>/`。不要覆盖同日旧运行或把用户已有归档当作新输出目录。保留原始 CSV 和生产配置。

证据至少包括：输入哈希与筛选规则、共同截止时间和窗口、逐腿费用依据、实际运行命令与退出状态、工具原输出；请求回放时追加研究配置、逐笔模拟成交与结果核对。缺少数据也保存缺项说明。

完成时保存 200–500 字交接：目标、改动／提交状态、验证、未决问题及证据路径。日报请求不自动创建定时任务；不以技能文字代替自动化配置，也不自动追加用户长期记忆。

完成请求的模式、输出与核对后停止。不要为“更稳妥”无限增加回测，也不要把修复采集器、调仓或安装技能混入分析任务。
